Initial release — optimise video uploads to WebM (VP9/Opus) in the background via Payload's Jobs Queue. The source file is always stored untouched; the upload response returns immediately with `status: 'queued'`, and a durable job (retries: 3, cron-safe, idempotent per preset) encodes one hidden sidecar document per configured preset in the same collection (same storage adapter), linked from the source via `webmVersions` rows and garbage-collected on file replacement and deletion. Named presets carry typed encoding overrides, with `resolutionPresets([360, 720, 1080])` shipping Google's VP9 CRF quality ladder. A dependency-free `/frontend` subpath provides `getVideoSources()` / `getWebmUrl()` — renditions in preference order with the original as the guaranteed fallback. Hosts control backgrounding via `dispatch` (Next `after`, `waitUntil`, `void run()`, or an external queue; unset = inline with a boot warning). Guardrails: `skipIfLarger` (per preset), `maxInputFileSize`, `maxConcurrentEncodes` (default 2), encode timeouts, init-time validation, and a boot-time ffmpeg/encoder check. A read-only `videoWebm` group tracks status, original file info, encode duration, skip reasons, and last error.
