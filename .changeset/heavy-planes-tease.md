Initial release — optimise video uploads to WebM (VP9/Opus) in the background via Payload's Jobs Queue. The source file is always stored untouched; the upload response returns immediately with `status: 'queued'`, and a durable job (retries: 3, cron-safe, idempotent per preset) encodes one hidden sidecar document per configured preset in the same collection (same storage adapter), linked from the source via `webmVersions` rows and garbage-collected on file replacement and deletion. Named presets carry typed encoding overrides: `widthPresets()` builds a width ladder spaced ~1.5× apart (the sizes a layout actually asks for), `resolutionPresets()` the height-based equivalent on Google's VP9 CRF table, and `sourcePreset()` a straight full-resolution conversion (nothing resized or cropped, inherited dimension caps cleared, stored as plain `clip.webm`). Presets may also carry an `aspectRatio` — the largest window of that shape, framed by the document's focal point, clamped inside the frame and cropped before scaling — which is what makes a 9:16 portrait rendition worth its encode when `object-fit: cover` on a landscape master would overdraw ~3×. `encoding.audio: false` drops the audio stream for muted background video. Every rendition's dimensions are measured off the encoded file and stored on its row, so selection needs no extra query and no shipped component: `pickVideoVariant(doc, { width, height, dpr })` chooses the smallest rendition covering a measured slot — switching to a differently-shaped family only when covering would overdraw too far — while `getVideoSourceSet(doc, { sizes })` emits `media`-gated `<source>` tags so the browser chooses with no JavaScript at all (evaluated once at load, so it suits static rendering rather than rotation). Helpers warn in development when `webmVersions` rows arrive unpopulated, which otherwise silently serves the original file. A dependency-free `/frontend` subpath provides `getVideoSources()` / `getWebmUrl()` — renditions in preference order with the original as the guaranteed fallback. Hosts control backgrounding via `dispatch` (Next `after`, `waitUntil`, `void run()`, or an external queue); with none configured the job runs inline, or detached once the upload commits on databases with transactions, and the plugin warns at boot. Guardrails: `skipIfLarger` and `skipRedundantPresets` (both per preset, both recorded on the document so nothing is re-encoded twice), `maxInputFileSize`, `maxConcurrentEncodes` (default 2), encode timeouts, init-time validation, and a boot-time ffmpeg/encoder check. Source videos are never held in memory — ffmpeg reads them from disk and remote storage is streamed to a temp file. Conversions are guarded by a `webmGeneration` counter and a merged final write, so a slow, duplicated or superseded run can never overwrite newer renditions, and renditions are only garbage-collected by writes that genuinely retire them (a new file, the job itself, or the regenerate endpoint) — never by an ordinary save, a restored version, or a duplicated document. Export `EXCLUDE_WEBM_DERIVATIVES` for `filterOptions` on relationship/upload fields and for your own queries, since `baseListFilter` only covers the admin list view. A live admin sidebar panel (via `./client` and the import map) polls while the job runs and shows a condensed table of the stored renditions — file size and savings, open-in-new-tab, and per-preset or full regeneration, with presets the job decided not to store collapsed into a single footnote naming them and why through a `POST /<taskSlug>/regenerate` endpoint gated by the collection's update access and rate-limited to one queued conversion per document; the underlying `videoWebm` group tracks status, original file info, encode duration, skip reasons, and last error through the API.
