Initial release — optimise video uploads to WebM (VP9/Opus) in the background via Payload's Jobs Queue. The source file is always stored untouched; the upload response returns immediately with `status: 'queued'`, and a durable job (retries: 3, cron-safe, idempotent per preset) encodes one hidden sidecar document per configured preset in the same collection (same storage adapter), linked from the source via `webmVersions` rows and garbage-collected on file replacement and deletion. Named presets carry typed encoding overrides, with `resolutionPresets([360, 720, 1080])` shipping Google's VP9 CRF quality ladder and `sourcePreset()` producing a straight full-resolution conversion of the source (nothing resized or cropped, inherited dimension caps cleared, stored as plain `clip.webm`). A dependency-free `/frontend` subpath provides `getVideoSources()` / `getWebmUrl()` — renditions in preference order with the original as the guaranteed fallback. Hosts control backgrounding via `dispatch` (Next `after`, `waitUntil`, `void run()`, or an external queue); with none configured the job runs inline, or detached once the upload commits on databases with transactions, and the plugin warns at boot. Guardrails: `skipIfLarger` and `skipRedundantPresets` (both per preset, both recorded on the document so nothing is re-encoded twice), `maxInputFileSize`, `maxConcurrentEncodes` (default 2), encode timeouts, init-time validation, and a boot-time ffmpeg/encoder check. Source videos are never held in memory — ffmpeg reads them from disk and remote storage is streamed to a temp file. Conversions are guarded by a `webmGeneration` counter and a merged final write, so a slow, duplicated or superseded run can never overwrite newer renditions, and renditions are only garbage-collected by writes that genuinely retire them (a new file, the job itself, or the regenerate endpoint) — never by an ordinary save, a restored version, or a duplicated document. Export `EXCLUDE_WEBM_DERIVATIVES` for `filterOptions` on relationship/upload fields and for your own queries, since `baseListFilter` only covers the admin list view. A live admin sidebar panel (via `./client` and the import map) polls while the job runs and shows a condensed per-preset table — file size and savings, skip reasons, open-in-new-tab, and per-preset or full regeneration through a `POST /<taskSlug>/regenerate` endpoint gated by the collection's update access and rate-limited to one queued conversion per document; the underlying `videoWebm` group tracks status, original file info, encode duration, skip reasons, and last error through the API.
